## 1. Cut Diff 2.0이란?

Cut Diff 2.0은 편집된 타임라인의 두 버전 — **이전 컷 (OLD)**과 **신규 컷 (NEW)** — 을 비교하여 두 버전 사이에서 정확히 무엇이 바뀌었는지 보여줍니다. 다음 질문에 답합니다:

- 어떤 클립이 추가, 삭제 또는 교체되었는가?
- 어떤 샷이 연장 또는 단축되었는가?
- 얼마나 많은 화면 시간이 추가 또는 삭제되었는가?
- 어떤 변경이 고위험으로 VFX/오디오/음악 부서의 즉각적인 주의가 필요한가?

**편집 턴오버**를 위해 설계되었습니다: VFX 코디네이터, 어시스턴트 에디터, 사운드 에디터, 음악 수퍼바이저 등 픽처 락 수정 사항을 빠르게 파악해야 하는 전문가를 위한 도구입니다.

**지원 파일 형식**: EDL (CMX 3600), FCPXML, ALE, DaVinci Resolve·Avid·Premiere·Final Cut Pro X의 XML 타임라인 내보내기.

## 2. 타임라인 불러오기

### 드롭 영역

탭 상단에 두 개의 드롭 영역이 있습니다:

```
┌────────────────────┐   ┌────────────────────┐
│  이전 타임라인 드롭│   │  신규 타임라인 드롭│
│  또는 Browse 클릭  │   │  또는 Browse 클릭  │
└────────────────────┘   └────────────────────┘
```

- **왼쪽 영역 = OLD** — 이전 버전 (참조/기준선)
- **오른쪽 영역 = NEW** — 편집팀에서 받은 업데이트 버전

각 영역에 파일을 드래그 앤 드롭하거나 **Browse**를 클릭하여 파일을 선택합니다. 파일이 불러와지면 영역에 파일명이 표시되고 하이라이트됩니다.

### 어느 것이 OLD이고 어느 것이 NEW인가?

항상 **더 이전** 버전을 OLD로, **더 최신** 버전을 NEW로 불러오세요. 차이 방향이 중요합니다: NEW 클립이 OLD 클립보다 길 때만 해당 이벤트가 EXTENDED로 표시됩니다. 반대로 불러오면 EXTENDED/TRIMMED 레이블이 모두 반전됩니다.

### 영상 파일 불러오기 (선택 사항이지만 권장)

드롭 영역 아래에 **Video Compare** 패널이 있습니다. OLD와 NEW의 실제 영상 파일을 선택적으로 드롭하거나 탐색할 수 있습니다. 이를 통해 다음이 활성화됩니다:

- 타임라인의 프레임 정확 썸네일 필름스트립
- Side-by-side / Wipe / 차이 영상 비교
- 타임라인 아래 픽셀 수준의 컨텐츠 차이 그래프

영상 파일은 브라우저의 IndexedDB에 저장되어 세션 간 기억됩니다.

## 3. 차이 분석 실행

헤더의 **Analyze** 버튼을 클릭합니다. 이렇게 하면 차이 엔진이 시작되어 다음을 수행합니다:

1. 두 타임라인의 모든 클립 파싱
2. **클립 식별** (클립 이름 + 릴)에 의해 각 NEW 클립을 OLD의 최적 대응 클립과 매칭
3. 각 매치를 차이 유형 (NEW, EXTENDED, CHANGED, TRIMMED)으로 분류
4. 각 변경에 대한 **위험도 점수** 계산
5. KPI 바, 타임라인, 테이블 렌더링

차이 분석은 브라우저 내에서 완전히 실행됩니다 — 업로드 없음, 서버 없음.

### KPI 바

분석 후 일련의 메트릭 카드가 나타납니다:

| 카드 | 표시 내용 |
|------|----------|
| **NEW** | NEW에 나타나지만 OLD에 매칭 클립이 없는 클립 |
| **EXTENDED** | OLD와 NEW 사이에 길이가 증가한 클립 |
| **CHANGED** | 클립 이름은 같지만 소재 또는 테이크가 다름 |
| **TRIMMED** | 길이가 감소한 클립 |
| **HIGH RISK** | 즉각적인 주의가 필요한 이벤트 (§5 참조) |
| **+DUR** | 추가된 총 화면 시간 (NEW + EXTENDED 프레임) |
| **−DUR** | 삭제된 총 화면 시간 (TRIMMED 프레임) |
| **% Changed** | 변경된 컷의 비율 |

## 4. 차이 유형 이해하기

엔진은 각 NEW 클립을 **같은 클립 이름과 릴**을 가진 OLD 클립과 비교합니다. 매치가 발견되면 작은 허용 오차 내 (길이 ±2프레임, source-in ±4프레임)에서 길이와 소스 인 포인트를 비교하여 차이 유형을 결정합니다.

### NEW
```
OLD: [없음]
NEW: [████████ CLIP_A ████████]
```
클립이 NEW에 존재하지만 OLD 어디에도 **같은 식별의 클립이 없습니다**. 모든 NEW 이벤트는 자동으로 **고위험**입니다.

### EXTENDED
```
OLD: [████████ CLIP_B ████████]         (200 프레임)
NEW: [█████████████ CLIP_B █████████]   (260 프레임 + 60 프레임 추가)
```
같은 클립이지만 NEW 버전이 **더 길다**. VFX의 경우 일반적으로 VFX 작업 창을 확장해야 함을 의미합니다.

### TRIMMED
```
OLD: [█████████████ CLIP_C █████████]   (180 프레임)
NEW: [████ CLIP_C ████]                  (80 프레임 — 100 프레임 삭제)
```
같은 클립이지만 NEW 버전이 **더 짧다**. VFX의 경우 예산보다 늦게 시작하거나 일찍 끝날 수 있습니다.

### CHANGED
```
OLD: [████ CLIP_D (srcIn=00:42:15:00) ████]
NEW: [████ CLIP_D (srcIn=01:12:30:08) ████]   같은 이름, 완전히 다른 소스
```
클립 이름은 같지만 소스 타임코드 (srcIn)가 허용 오차 이상으로 다릅니다. 다른 테이크, 리타임 또는 재그레이딩 버전, 같은 이름의 교체 클립을 나타냅니다.

### UNCHANGED
```
OLD: [████ CLIP_E ████]  (srcIn=00:10:00:00, dur=120fr)
NEW: [████ CLIP_E ████]  (srcIn=00:10:00:00, dur=120fr) — 동일
```
두 버전에서 허용 오차 내로 클립이 동일합니다. 기본적으로 UNCHANGED 이벤트는 테이블에서 **숨겨집니다**.

## 5. 위험도 점수

모든 차이 이벤트는 다운스트림 작업에 미치는 영향에 따라 위험 수준이 부여됩니다.

### 위험 수준

| 수준 | 색상 | 규칙 |
|------|------|------|
| **높음** | 🔴 빨강 | 모든 NEW 이벤트 **또는** 240프레임 초과 (~10초 @24fps) 이벤트 |
| **중간** | 🟡 앰버 | 이벤트 길이 48~240프레임 (~2~10초) |
| **낮음** | 🟢 초록 | 이벤트 길이 48프레임 미만 (~2초) |

### 매치 점수 (신뢰도 %)

EXTENDED, CHANGED, TRIMMED 이벤트에 대해 엔진은 0~100%의 **매치 신뢰도**도 보고합니다:

- **100%**: 완벽한 매치
- **75~99%**: 작은 트림 또는 작은 소스 조정 — 높은 신뢰도
- **50~74%**: 중간 정도의 차이 — 재확인 필요
- **< 50%**: 큰 차이 — 잘못된 매치 가능성

점수 계산식:
`(길이 유사도 × 60%) + (source-in 유사도 × 40%)`

## 6. 타임라인 읽기

타임라인은 Cut Diff 2.0의 가장 강력한 부분입니다. OLD와 NEW 컷 **모두**를 수평 트랙으로 나란히 표시합니다.

### 타임라인 레이아웃 (위에서 아래로)

```
┌─────────────────────────────────────────────────────────────┐
│ RULER  │ 00:00   00:30   01:00   01:30   02:00              │ ← 타임코드 룰러
├────────────────────────────────────────────────────────────┤
│  OLD ░░░░▓▓▓▓▓░░▓▓▓▓░░░░░░▓▓░░░░░░▓▓▓░░░░░░░░░░░░░░░░░░░  │ ← OLD 트랙
│ ─────────────────── DIFF ──────────────────────────────────── │ ← 차이 구분선
│  NEW ░░░▓▓▓▓░░░░░░░▓▓▓▓▓▓░░░▓░░░░░░░▓▓▓░░░░░░░░░░░░░░░░░░  │ ← NEW 트랙
│ ▓▓▓░░░░▓▓▓░▓░▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │ ← 요약 스트립
├────────────────────────────────────────────────────────────┤
│ Content diff ░░▓░░░░░░▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │ ← 픽셀 차이 그래프
└─────────────────────────────────────────────────────────────┘
```

### NEW 트랙과 차이 컬러 바

NEW 트랙은 차이 상태를 나타내는 **컬러 바**와 함께 각 클립을 표시합니다:

| 색상 | 차이 유형 | 의미 |
|------|----------|------|
| 🔵 밝은 시안 | NEW | 처음 등장 — OLD에 없음 |
| 🟢 초록 | EXTENDED | 이 클립이 OLD보다 길어짐 |
| 🟡 앰버 | CHANGED | 같은 이름, 다른 소스/테이크 |
| 🟣 보라 | TRIMMED | 이 클립이 OLD보다 짧아짐 |
| ⬛ 매우 어두운 | UNCHANGED | OLD와 동일 |

클립 상단의 **2px 빨간 스트라이프**는 고위험을 의미합니다.

### 컨텐츠 차이 그래프

요약 스트립 아래의 바 그래프는 OLD와 NEW 사이의 **픽셀 수준 프레임 유사도**를 표시합니다.

| 색상 | 의미 |
|------|------|
| 🟢 초록 바 | 프레임이 거의 동일하게 보임 |
| 🟡 앰버 바 | 중간 정도의 시각적 차이 |
| 🔴 빨간 바 | 프레임이 시각적으로 매우 다름 |

## 7. 샷 컷과 식별 방법

### 타임라인에서 샷 컷 보기

**방법 1: NEW 트랙에서 클립의 시작/끝 지점 확인**

인접한 클립의 컬러 차이 바가 다른 유형일 때, 중요한 편집 포인트 변화가 있습니다.

**방법 2: 변경된 섹션으로 확대**

타임라인에서 **스크롤 휠로 확대**합니다. 확대하면 룰러 눈금이 세밀해지고 개별 샷이 보입니다.

**방법 3: 요약 스트립의 클러스터 주시**

요약 스트립은 전체 컷을 하나의 바로 압축하여 표시합니다. 색상 클러스터 (시안/앰버/초록)는 밀집된 수정 구역을 나타냅니다.

**방법 4: OLD와 NEW 클립 가장자리 직접 비교**

테이블에서 TRIMMED 이벤트를 선택합니다. 인스펙터에서 OLD와 NEW의 `RecIn`/`RecOut` 값을 볼 수 있습니다. 차이가 컷 포인트가 이동한 양입니다.

### 기존 샷 사이에 삽입된 NEW 클립

기존 클립 사이에 NEW 클립이 나타나면 후속 클립의 레코드 인 타임코드가 이동합니다:

```
OLD:  [──A──|──B──|──C──]      B는 01:00:00:00에서 시작
NEW:  [──A──|NEW X|──B──|──C──]  B는 이제 01:00:12:00에서 시작
```

NEW 컷의 B는 UNCHANGED (같은 콘텐츠)이지만 프로그램에서 **더 늦게** 나타납니다. 이것은 다음에 영향을 미칩니다:
- **음악 에디터**: B의 액션 비트에 맞춘 큐가 이제 12초 늦어짐
- **사운드 에디터**: B에 동기화된 폴리와 효과는 리타임 필요
- **VFX**: B의 VFX 샷이 이제 다른 프로그램 위치에서 재생됨

## 8. 차이 테이블

테이블은 변경된 모든 이벤트를 행으로 나열합니다.

### 열 가이드

| 열 | 설명 |
|----|------|
| **●** | 위험도 표시 — 빨강 (높음), 앰버 (중간), 초록 (낮음) |
| **Type** | NEW / EXT / CHG / TRM / UNC 배지 |
| **Reel** | EDL/XML의 릴 또는 빈 이름 |
| **Clip** | 클립 이름 |
| **SrcIn** | 소스 타임코드 인 |
| **Dur** | 프레임 단위 길이 |
| **Match%** | 신뢰도 점수 (바 + %) — NEW 이벤트는 공백 |
| **Status** | 리뷰 상태: — / ✓ / ⊘ / ? (클릭으로 전환) |
| **Note** | 자유 텍스트 메모 필드 (인스펙터에서 표시) |

### 행 선택

아무 행이나 클릭하면:
1. 완전한 이벤트 세부 정보와 함께 **인스펙터** (오른쪽 패널)가 열림
2. 해당 이벤트가 중앙에 오도록 **타임라인이 확대**됨
3. 이벤트의 `RecIn` 타임코드로 **영상이 탐색**됨 (영상이 로드된 경우)

## 9. 인스펙터 패널

아무 행이나 클릭하면 오른쪽에 인스펙터가 열립니다. 선택한 변경 사항의 완전한 분석이 표시됩니다.

### 필드

```
이벤트 3 / 47                ← 전체 이벤트 번호
Type:    EXTENDED             ← 차이 분류
Reel:    A001                 ← 릴 이름
Clip:    105_08_06/01_AB      ← 클립 이름
SrcIn:   10:42:15:00          ← NEW의 소스 시작
SrcOut:  10:42:28:10          ← NEW의 소스 끝
RecIn:   01:02:45:00          ← 레코드 (프로그램) 시작
RecOut:  01:02:58:10          ← 레코드 (프로그램) 끝
Duration: 318 프레임
FPS:      24
```

### 매치 정보 (EXTENDED / TRIMMED / CHANGED용)

```
Match Score:  ████████░░  78%  ← 신뢰도 바
Reason:       Duration +48fr (+2.0s extended)
Old Clip:     105_08_06/01_AB  ← OLD의 같은 클립
Old SrcIn:    10:42:15:00      ← OLD의 소스 시작
Old RecIn:    01:02:45:00      ← OLD의 레코드 시작
```

### 상태와 메모

**상태** (클릭 또는 Enter로 전환):
- **—** (없음): 아직 리뷰 안 됨
- **✓** (확인): 확인 완료, 조치 불필요
- **⊘** (건너뜀): 알려진 문제, 이번 패스에서 건너뜀
- **?** (문의): 후속 조치 또는 논의 필요

메모는 PDF와 XLSX 내보내기 모두에 표시됩니다.

---

## 10. 영상 비교

OLD와 NEW의 영상 파일을 불러와 전체 비교 패널을 활성화합니다.

### 비교 모드

#### Wipe (와이프)
수직 슬라이더가 화면을 분할합니다. 슬라이더를 좌우로 드래그하여 OLD (왼쪽) 또는 NEW (오른쪽)를 표시합니다.

#### Side by Side (사이드 바이 사이드, SBS)
OLD는 왼쪽 절반에서, NEW는 오른쪽 절반에서 동시에 재생됩니다. 둘 다 동기화되어 재생됩니다.

#### Split (분할)
SBS와 유사하지만 각 영상이 각자의 절반을 완전히 채웁니다 (크롭).

#### AB
한 번에 하나의 영상을 전체 화면으로 표시합니다. 캔버스를 클릭하여 A (OLD)와 B (NEW) 사이를 전환합니다.

#### Diff (차이)
**픽셀 단위 차이 이미지**를 표시합니다: 동일한 픽셀은 검게, 다른 픽셀은 밝게 나타납니다.

#### Heat (히트맵)
Diff와 유사하지만 크기에 따라 색상 코딩:
- 🟢 초록: 작은 변화
- 🟡 앰버: 중간 변화
- 🔴 빨강: 큰 변화

### Chain 모드

Chain이 활성화되면 이벤트를 선택할 때 OLD 영상이 자동으로 **OLD 클립의 소스 인**으로 탐색되고, NEW도 NEW 클립의 소스 인으로 탐색됩니다. 편집자가 다른 테이크로 전환한 CHANGED 이벤트를 검토할 때 Chain을 사용합니다.

## 11. 필터

### 유형 필터

알약 버튼을 클릭하여 특정 차이 유형만 표시:

`ALL` `NEW` `EXTENDED` `CHANGED` `TRIMMED`

### 위험도 필터

`all` `high` `med` `low`

**high**를 클릭하여 고위험 이벤트만 봅니다. 모든 턴오버 리뷰의 권장 시작점입니다.

### 필터 함께 사용하기

필터는 조합됩니다: 유형 필터와 위험도 필터 모두 적용됩니다. NEW 샷이 아닌 고위험 변경만 보려면 type=EXTENDED, risk=high로 설정합니다.

## 12. 상태 및 메모 워크플로우

### 권장 리뷰 패스

1. **HIGH RISK로 필터** → 모든 HIGH 항목 리뷰 → ✓ (확인) 또는 ? (문의)로 표시
2. **CHANGED로 필터** → 각 테이크 교체 확인 → VFX 재작업 필요 시 메모
3. **NEW로 필터** → 코디네이터와 새 샷 확인 → 풀/납품 날짜 메모
4. **EXTENDED로 필터** → VFX 샷이 예산 초과로 연장되지 않았는지 확인
5. **TRIMMED로 필터** → 납품물이 단축된 창에 맞는지 확인

### 실제 상태의 의미

| 상태 | 사용 시기 |
|------|---------|
| **—** | 아직 리뷰 안 됨 |
| **✓ 확인** | 리뷰 완료, 조치 불필요, 안전하게 진행 가능 |
| **⊘ 건너뜀** | 알려진/의도적, 이번 세션 건너뜀 |
| **? 문의** | 조치 전 에디터/코디네이터에게 문의 필요 |

## 13. 내보내기

앰버색 **Export ▾** 버튼을 클릭하여 내보내기 메뉴를 엽니다.

### Pull EDL

**NEW, CHANGED, EXTENDED** 이벤트만 포함하는 CMX 3600 EDL을 생성합니다. 상태가 **⊘ 건너뜀**인 이벤트는 제외됩니다.

### PDF 리포트

새 브라우저 탭에서 인쇄 준비된 PDF가 열립니다:
- **요약 헤더**: 프로젝트 이름, OLD/NEW 파일 이름, 날짜, 통계 칩
- **변경 카드**: 변경된 이벤트마다 하나의 카드, 유형별 그룹화
- **오디오 변경 목록**: 오디오 트랙 클립을 위한 별도 테이블

### XLSX 변경 목록

**썸네일 이미지가 내장된** `.xlsx` 워크북 (4개 시트)을 내보냅니다:

| 시트 | 내용 |
|------|------|
| **Change List** | 120×68 썸네일이 있는 모든 변경된 이벤트 |
| **Audio Ref** | RecIn으로 정렬된 모든 이벤트, 오디오 플래그 포함 |
| **Removed** | OLD에 있지만 NEW에 없는 클립 |
| **Summary** | 통계 개요: 수, 길이 |

## 15. 팁과 워크플로우 예시

### 팁 1: 타임라인에서 바깥쪽으로 작업하기

테이블에서 시작하지 마세요 — 타임라인에서 시작합니다. 요약 스트립은 변경 사항이 어디에 집중되어 있는지 보여줍니다. 밀집된 클러스터로 확대하고, 샷 경계를 찾은 다음, 개별 이벤트를 클릭하여 인스펙터로 깊이 들어갑니다.

### 팁 2: Wipe 모드로 프레이밍 변화 확인

매치 점수가 높은 (>75%) CHANGED 이벤트는 에디터가 약간 다른 시작 프레임을 사용했다는 것을 자주 의미합니다. Wipe 모드로 전환하고 샷의 첫 번째 프레임으로 스크럽합니다.

### 팁 3: 자동 교체를 위한 컨텐츠 차이 그래프 활용

컨텐츠 차이 그래프는 EDL이 캡처할 수 없는 변경 사항을 잡습니다. NEW 트랙에 컬러 바가 없는 영역 아래의 그래프에서 스파이크가 보이면, 클립 이름/타임코드는 동일하지만 콘텐츠가 시각적으로 다릅니다.

### 팁 4: 가장 복잡한 문제는 HIGH + CHANGED 필터 사용

고위험 + CHANGED 유형의 조합이 가장 까다로운 시나리오입니다: 기존의 긴 샷이 다른 테이크로 교체되었습니다. type=CHANGED, risk=high로 설정하여 이를 분리합니다.

### 팁 5: 메모를 납품 메모로 활용

리뷰하면서 Note 필드에 직접 행동 항목을 입력합니다. XLSX를 내보내면 모든 메모가 스프레드시트에 있어 VFX 코디네이터나 음악 에디터와 공유할 준비가 됩니다.

### 팁 6: 테이크 비교에 AB 모드 사용

CHANGED 이벤트를 리뷰할 때, AB 모드로 들어가 이벤트를 선택하고 캔버스를 빠르게 클릭하여 A/B를 전환합니다. Chain 모드가 두 영상을 샷 시작점에 맞추기 때문에, 정확히 같은 장면의 OLD 테이크와 NEW 테이크 사이를 전환하고 있습니다.

### 팁 7: 대형 컨폼에는 Multi-Part EDL 활용

시퀀스에 변경된 이벤트가 1,500개 이상 있으면 Pull EDL 내보내기가 자동으로 여러 파일로 분할됩니다 (파트1, 파트2, …).
