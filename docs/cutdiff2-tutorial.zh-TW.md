## 1. 什麼是 Cut Diff 2.0？

Cut Diff 2.0 比對兩個版本的剪輯時間軸 — **舊版剪輯 (OLD)** 與**新版剪輯 (NEW)** — 並精確顯示兩者之間的變更內容。它能回答以下問題：

- 哪些片段被新增、刪除或替換？
- 哪些鏡頭被延長或縮短？
- 增加或刪除了多少銀幕時間？
- 哪些變更屬於高風險，需要 VFX／聲音／音樂部門立即關注？

專為**剪輯交接**而設計：VFX 協調人員、助理剪輯師、聲音剪輯師和音樂總監，需要迅速理解鎖定版本修訂內容的專業人士。

**支援的檔案格式**：EDL (CMX 3600)、FCPXML、ALE、來自 DaVinci Resolve、Avid、Premiere 和 Final Cut Pro X 的 XML 時間軸匯出。

## 2. 載入時間軸

### 拖放區域

標籤頁上方有兩個拖放區域：

```
┌────────────────────┐   ┌────────────────────┐
│  拖放舊版時間軸     │   │  拖放新版時間軸     │
│  或點擊 Browse     │   │  或點擊 Browse     │
└────────────────────┘   └────────────────────┘
```

- **左側區域 = OLD** — 前一版本（您的參考基準）
- **右側區域 = NEW** — 從剪輯部門收到的更新版本

將檔案拖放到各個區域，或點擊 **Browse** 選取檔案。載入檔案後，檔名會顯示在區域中，且區域會變為高亮顯示。

### 哪個是 OLD？哪個是 NEW？

請務必將**較早**的版本載入為 OLD，**較新**的版本載入為 NEW。差異分析方向很重要：當 NEW 的片段比 OLD 的片段長時，該事件才會標記為 EXTENDED。若載入順序相反，所有 EXTENDED／TRIMMED 標籤都會對調。

### 載入影片檔案（可選但建議）

拖放區域下方是 **Video Compare** 面板。您可以選擇性地拖放或瀏覽 OLD 和 NEW 的實際影片檔案，這可啟用：

- 時間軸上精確到幀的縮圖膠卷條
- Side-by-side／Wipe／差異影片比對
- 時間軸下方的像素級內容差異圖表

影片檔案儲存在瀏覽器的 IndexedDB 中，可跨工作階段記憶。

## 3. 執行差異分析

點擊標題中的 **Analyze** 按鈕，這會啟動差異引擎，執行以下步驟：

1. 從兩個時間軸解析所有片段
2. 根據**片段識別** (片段名稱 + 卷號) 將每個 NEW 片段與 OLD 中最佳對應片段配對
3. 將每個配對分類為差異類型 (NEW、EXTENDED、CHANGED、TRIMMED)
4. 計算每項變更的**風險分數**
5. 呈現 KPI 列、時間軸和表格

差異分析完全在瀏覽器中執行 — 無需上傳，無需伺服器。

### KPI 列

分析後，一排指標卡片會出現：

| 卡片 | 顯示內容 |
|------|---------|
| **NEW** | 出現在 NEW 但在 OLD 中沒有對應片段的片段 |
| **EXTENDED** | OLD 和 NEW 之間時長增加的片段 |
| **CHANGED** | 片段名稱相同但素材或拍攝版本不同 |
| **TRIMMED** | 時長縮短的片段 |
| **HIGH RISK** | 需要立即關注的事件 (見第5節) |
| **+DUR** | 新增的總銀幕時間 (NEW + EXTENDED 幀數) |
| **−DUR** | 刪除的總銀幕時間 (TRIMMED 幀數) |
| **% Changed** | 剪輯中已變更的比例 |

## 4. 了解差異類型

引擎將每個 NEW 片段與**相同片段名稱和卷號**的 OLD 片段進行比對。找到配對後，在小容差範圍內 (時長 ±2 幀、源入點 ±4 幀) 比較時長和源入點，以決定差異類型。

### NEW
```
OLD: [無]
NEW: [████████ CLIP_A ████████]
```
片段存在於 NEW，但 OLD 中**沒有任何相同識別的片段**。所有 NEW 事件自動為**高風險**。

### EXTENDED
```
OLD: [████████ CLIP_B ████████]         (200 幀)
NEW: [█████████████ CLIP_B █████████]   (260 幀 + 新增 60 幀)
```
相同片段，但 NEW 版本**更長**。對於 VFX，這通常意味著需要擴展 VFX 工作視窗。

### TRIMMED
```
OLD: [█████████████ CLIP_C █████████]   (180 幀)
NEW: [████ CLIP_C ████]                  (80 幀 — 刪除 100 幀)
```
相同片段，但 NEW 版本**更短**。對於 VFX，工作可能現在比預算的開始更晚或結束更早。

### CHANGED
```
OLD: [████ CLIP_D (srcIn=00:42:15:00) ████]
NEW: [████ CLIP_D (srcIn=01:12:30:08) ████]   相同名稱，完全不同的來源
```
相同的片段名稱，但源時間碼 (srcIn) 的差異超過容差。表示：不同的拍攝版本、變速或重新調色的版本、或共用相同名稱的替換片段。

### UNCHANGED
```
OLD: [████ CLIP_E ████]  (srcIn=00:10:00:00, dur=120fr)
NEW: [████ CLIP_E ████]  (srcIn=00:10:00:00, dur=120fr) — 完全相同
```
兩個版本中的片段在容差範圍內相同。預設情況下，UNCHANGED 事件從表格中**隱藏**。

## 5. 風險評分

每個差異事件都會根據其對後期工作的影響獲得風險等級。

### 風險等級

| 等級 | 顏色 | 規則 |
|------|------|------|
| **高** | 🔴 紅色 | 任何 NEW 事件**或**任何持續超過 240 幀 (~10 秒，以 24fps 計) 的事件 |
| **中** | 🟡 琥珀色 | 事件時長 48–240 幀 (~2–10 秒) |
| **低** | 🟢 綠色 | 事件時長不足 48 幀 (~2 秒) |

### 配對分數（信心度 %）

對於 EXTENDED、CHANGED 和 TRIMMED 事件，引擎還會報告 0–100% 的**配對信心度**：

- **100%**：完美配對
- **75–99%**：小幅剪切或小幅源調整 — 高信心度
- **50–74%**：中等差異 — 值得仔細確認
- **< 50%**：大幅差異 — 可能是錯誤配對

分數計算方式：
`(時長相似度 × 60%) + (源入點相似度 × 40%)`

## 6. 解讀時間軸

時間軸是 Cut Diff 2.0 最強大的部分。它以水平軌道並排顯示 OLD 和 NEW 兩個版本。

### 時間軸佈局（從上到下）

```
┌─────────────────────────────────────────────────────────────┐
│ RULER  │ 00:00   00:30   01:00   01:30   02:00              │ ← 時間碼標尺
├────────────────────────────────────────────────────────────┤
│  OLD ░░░░▓▓▓▓▓░░▓▓▓▓░░░░░░▓▓░░░░░░▓▓▓░░░░░░░░░░░░░░░░░░░  │ ← OLD 軌道
│ ─────────────────── DIFF ──────────────────────────────────── │ ← 差異分隔線
│  NEW ░░░▓▓▓▓░░░░░░░▓▓▓▓▓▓░░░▓░░░░░░░▓▓▓░░░░░░░░░░░░░░░░░░  │ ← NEW 軌道
│ ▓▓▓░░░░▓▓▓░▓░▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │ ← 摘要條
├────────────────────────────────────────────────────────────┤
│ Content diff ░░▓░░░░░░▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │ ← 像素差異圖表
└─────────────────────────────────────────────────────────────┘
```

### NEW 軌道與差異顏色條

NEW 軌道顯示每個片段，底部有**彩色條**指示其差異狀態：

| 顏色 | 差異類型 | 含義 |
|------|---------|------|
| 🔵 亮青色 | NEW | 全新內容 — 不存在於 OLD |
| 🟢 綠色 | EXTENDED | 此片段比 OLD 更長 |
| 🟡 琥珀色 | CHANGED | 相同名稱，不同來源/版本 |
| 🟣 紫色 | TRIMMED | 此片段比 OLD 更短 |
| ⬛ 極深色 | UNCHANGED | 與 OLD 完全相同 |

片段頂部的 **2px 紅色條紋**表示高風險。

### 內容差異圖表

摘要條下方的長條圖顯示 OLD 和 NEW 之間**像素級幀相似度**。

| 顏色 | 含義 |
|------|------|
| 🟢 綠色長條 | 幀看起來幾乎相同 |
| 🟡 琥珀色長條 | 中等視覺差異 |
| 🔴 紅色長條 | 幀在視覺上差異很大 |

## 7. 剪接點與辨識方法

### 如何在時間軸中看到剪接點

**方法 1：查看 NEW 軌道中片段的起點/終點**

當相鄰片段的彩色差異條類型不同時，表示有重要的編輯點變更。

**方法 2：放大到有變更的區段**

在時間軸上使用**滾輪縮放**。縮放後，標尺刻度變細，個別鏡頭變得清晰可見。

**方法 3：注意摘要條中的色塊群**

摘要條將整個剪輯壓縮成一條。一個顏色群集（青色/琥珀色/綠色）表示密集的修訂區域。

**方法 4：直接比較 OLD 和 NEW 的片段邊緣**

在表格中選擇 TRIMMED 事件。檢視面板顯示 OLD 和 NEW 的 `RecIn`/`RecOut` 值。差異即為剪接點移動的距離。

### NEW 片段插入既有鏡頭之間

當 NEW 片段出現在已知片段之間時，後續片段的記錄入點時間碼將會偏移：

```
OLD:  [──A──|──B──|──C──]      B 從 01:00:00:00 開始
NEW:  [──A──|NEW X|──B──|──C──]  B 現在從 01:00:12:00 開始
```

NEW 版本中的 B 是 UNCHANGED（相同內容），但在節目中**較晚**出現。這對以下工作有影響：
- **音樂剪輯師**：配合 B 動作節拍的音樂現在晚了 12 秒
- **聲音剪輯師**：同步到 B 的音效和擬音需要重新計時
- **VFX**：B 上的任何 VFX 鏡頭現在在不同的節目位置播放

## 8. 差異表格

表格將每個有變更的事件列為一行。

### 欄位說明

| 欄位 | 說明 |
|------|------|
| **●** | 風險指示點 — 紅色（高）、琥珀色（中）、綠色（低） |
| **Type** | NEW / EXT / CHG / TRM / UNC 徽章 |
| **Reel** | 來自 EDL/XML 的卷號或素材庫名稱 |
| **Clip** | 片段名稱 |
| **SrcIn** | 源入點時間碼 |
| **Dur** | 以幀為單位的時長 |
| **Match%** | 信心分數（進度條 + %）— NEW 事件為空白 |
| **Status** | 您的審查狀態：— / ✓ / ⊘ / ?（點擊循環切換） |
| **Note** | 自由文字備註欄（在檢視面板中可見） |

### 選取行

點擊任意行可：
1. **開啟檢視面板**（右側面板），顯示完整的事件詳情
2. **縮放時間軸**，將該事件置於中心
3. **定位影片**至事件的 `RecIn` 時間碼（若已載入影片）

## 9. 檢視面板

點擊任意行即可開啟右側的檢視面板，顯示所選變更的完整分析。

### 欄位

```
事件 3 / 47                  ← 事件編號（共幾個）
Type:    EXTENDED             ← 差異分類
Reel:    A001                 ← 卷號名稱
Clip:    105_08_06/01_AB      ← 片段名稱
SrcIn:   10:42:15:00          ← NEW 中的源入點
SrcOut:  10:42:28:10          ← NEW 中的源出點
RecIn:   01:02:45:00          ← 記錄（節目）入點
RecOut:  01:02:58:10          ← 記錄（節目）出點
Duration: 318 幀
FPS:      24
```

### 配對資訊（用於 EXTENDED / TRIMMED / CHANGED）

```
Match Score:  ████████░░  78%  ← 信心度進度條
Reason:       Duration +48fr (+2.0s extended)
Old Clip:     105_08_06/01_AB  ← OLD 中的相同片段
Old SrcIn:    10:42:15:00      ← OLD 中的源入點
Old RecIn:    01:02:45:00      ← OLD 中的記錄入點
```

### 狀態與備註

**狀態**（點擊或按 Enter 循環切換）：
- **—**（無）：尚未審查
- **✓**（確認）：已確認，無需採取行動
- **⊘**（跳過）：已知問題，本次略過
- **?**（待查）：需要跟進或討論

備註會出現在 PDF 和 XLSX 匯出中，您可以直接在此欄位為剪輯師或 VFX 總監寫一行說明。

## 10. 影片比對

為 OLD 和 NEW 載入影片檔案，以解鎖完整的比對面板。

### 比對模式

#### Wipe（擦拭）
一個垂直滑桿分割畫面。左右拖動滑桿以顯示 OLD（左）或 NEW（右）。

#### Side by Side（並排，SBS）
OLD 在左半播放，NEW 在右半同時播放，兩者同步。

#### Split（分割）
類似 SBS，但每個影片完全填滿各自的半邊（裁切）。

#### AB
每次全螢幕顯示一個影片。點擊畫布在 A（OLD）和 B（NEW）之間切換。

#### Diff（差異）
顯示**逐像素差異圖像**：相同的像素顯示為黑色，不同的像素顯示為亮色。

#### Heat（熱圖）
類似 Diff，但按差異程度使用顏色編碼：
- 🟢 綠色：小幅變化
- 🟡 琥珀色：中等變化
- 🔴 紅色：大幅變化

### Chain 模式

啟用 Chain 時，選擇事件後，OLD 影片會自動定位至 **OLD 片段的源入點**，NEW 影片也會定位至 NEW 片段的源入點。審查 CHANGED 事件時使用 Chain 模式。

## 11. 篩選器

### 類型篩選器

點擊膠囊按鈕以僅顯示特定差異類型：

`ALL` `NEW` `EXTENDED` `CHANGED` `TRIMMED`

### 風險篩選器

`all` `high` `med` `low`

點擊 **high** 僅查看高風險事件。這是任何交接審查的建議起點。

### 同時使用篩選器

篩選器可組合使用：類型篩選器和風險篩選器同時生效。若要查看所有非新增鏡頭的高風險變更，設定 type=EXTENDED 且 risk=high。

## 12. 狀態與備註工作流程

### 建議的審查流程

1. **篩選 HIGH RISK** → 審查所有 HIGH 項目 → 標記為 ✓（確認）或 ?（待查）
2. **篩選 CHANGED** → 檢查每個版本替換 → 記錄是否需要 VFX 重新製作
3. **篩選 NEW** → 與協調人員確認新鏡頭 → 記錄調取/交付日期
4. **篩選 EXTENDED** → 確認是否有 VFX 鏡頭超出預算
5. **篩選 TRIMMED** → 確認可交付成果仍符合縮短後的視窗

### 實際操作中的狀態含義

| 狀態 | 使用時機 |
|------|---------|
| **—** | 尚未審查 |
| **✓ 確認** | 已審查，無需行動，可安全進行 |
| **⊘ 跳過** | 已知／刻意為之，本次略過 |
| **? 待查** | 需要先詢問剪輯師／協調人員再行動 |

## 13. 匯出

點擊琥珀色的 **Export ▾** 按鈕開啟匯出選單。

### Pull EDL

生成 CMX 3600 EDL，僅包含 **NEW、CHANGED 和 EXTENDED** 事件。狀態為 **⊘ 跳過**的事件將被排除。

### PDF 報告

在新的瀏覽器分頁中開啟列印就緒的 PDF，包含：
- **摘要標題**：專案名稱、OLD/NEW 檔案名稱、日期、統計資訊
- **變更卡片**：每個有變更的事件一張卡片，按類型分組
- **音訊變更清單**：音訊軌道片段的獨立表格

### XLSX 變更清單

匯出 `.xlsx` 活頁簿（4 個工作表），含**嵌入的縮圖圖片**：

| 工作表 | 內容 |
|--------|------|
| **Change List** | 所有有變更的事件，含 120×68 縮圖 |
| **Audio Ref** | 所有事件按 RecIn 排序，標記音訊相關性 |
| **Removed** | 存在於 OLD 但不存在於 NEW 的片段 |
| **Summary** | 統計概覽：數量、時長 |

## 15. 技巧與工作流程範例

### 技巧 1：從時間軸開始向外展開

不要從表格開始 — 從時間軸開始。摘要條顯示變更集中在哪裡。放大密集的群集，找到鏡頭邊界，然後點擊個別事件深入檢視面板。

### 技巧 2：使用 Wipe 模式檢查構圖變更

配對分數高（>75%）的 CHANGED 事件通常意味著剪輯師使用了稍微不同的起始幀。切換到 Wipe 模式並定格到鏡頭的第一幀。

### 技巧 3：注意內容差異圖表中的靜默替換

內容差異圖表能捕捉 EDL 無法捕捉到的變更。如果您在圖表中看到峰值，但 NEW 軌道中該區域沒有彩色條，片段名稱/時間碼相同但內容在視覺上有所不同。

### 技巧 4：篩選 HIGH + CHANGED 處理最複雜的問題

高風險 + CHANGED 類型是最複雜的情況：一個現有的長鏡頭被不同版本替換。設定 type=CHANGED 且 risk=high 以篩選出這些情況。

### 技巧 5：將備註用作交付備忘錄

審查時直接在備註欄位輸入您的行動項目。匯出 XLSX 時，每條備註都在試算表中 — 準備好與 VFX 協調人員或音樂剪輯師分享。

### 技巧 6：使用 AB 模式進行版本比對

審查 CHANGED 事件時，進入 AB 模式，選擇事件，然後快速點擊畫布切換 A/B。由於 Chain 模式將兩個影片對齊到鏡頭起點，您是在同一場景的 OLD 版本和 NEW 版本之間切換。

### 技巧 7：大型套底作業使用多部分 EDL

如果您的序列有超過 1,500 個有變更的事件，Pull EDL 匯出會自動分割成多個檔案（第1部分、第2部分……）。
