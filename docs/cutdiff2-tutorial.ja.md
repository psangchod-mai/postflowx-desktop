## 1. Cut Diff 2.0 とは

Cut Diff 2.0 は、編集済みタイムラインの 2 つのバージョン — **旧バージョン (OLD)** と**新バージョン (NEW)** — を比較し、両者の差異を正確に表示します。以下の質問に答えます：

- どのクリップが追加・削除・置換されたか？
- どのショットが延長または短縮されたか？
- スクリーンタイムはどれだけ追加または削除されたか？
- どの変更が高リスクで、VFX／音響／音楽部門の即座の対応が必要か？

**編集ターンオーバー**向けに設計されています：VFX コーディネーター、アシスタントエディター、サウンドエディター、音楽スーパーバイザーなど、ピクチャーロック修正を素早く把握する必要がある専門家のためのツールです。

**対応ファイル形式**：EDL (CMX 3600)、FCPXML、ALE、DaVinci Resolve・Avid・Premiere・Final Cut Pro X からの XML タイムラインエクスポート。

## 2. タイムラインの読み込み

### ドロップゾーン

タブの上部に 2 つのドロップゾーンがあります：

```
┌────────────────────┐   ┌────────────────────┐
│  旧タイムラインを  │   │  新タイムラインを  │
│  ドロップまたは    │   │  ドロップまたは    │
│  Browse をクリック │   │  Browse をクリック │
└────────────────────┘   └────────────────────┘
```

- **左ゾーン = OLD** — 以前のバージョン（参照/ベースライン）
- **右ゾーン = NEW** — 編集部門から受け取った更新バージョン

各ゾーンにファイルをドラッグ＆ドロップするか、**Browse** をクリックしてファイルを選択します。ファイルが読み込まれると、ゾーンにファイル名が表示されてハイライトされます。

### OLD と NEW の見分け方

常に**古い**バージョンを OLD として、**新しい**バージョンを NEW として読み込んでください。差分の方向は重要です。NEW のクリップが OLD のクリップより長い場合にのみ、そのイベントは EXTENDED とマークされます。逆に読み込むと、すべての EXTENDED/TRIMMED ラベルが反転します。

### ビデオファイルの読み込み（任意だが推奨）

ドロップゾーンの下に **Video Compare** パネルがあります。OLD と NEW の実際のビデオファイルをドロップまたは参照することができます。これにより以下が有効になります：

- タイムライン上のフレーム精度のサムネイルフィルムストリップ
- Side-by-side / Wipe / 差分ビデオ比較
- タイムライン下部のピクセルレベルのコンテンツ差分グラフ

ビデオファイルはブラウザーの IndexedDB に保存されるため、セッション間で記憶されます。

## 3. 差分の実行

ヘッダーの **Analyze** ボタンをクリックします。これにより差分エンジンが起動し、以下を実行します：

1. 両方のタイムラインからすべてのクリップを解析
2. **クリップ識別**（クリップ名 + リール）によって各 NEW クリップを OLD の最良の対応クリップと照合
3. 各マッチを差分タイプ (NEW、EXTENDED、CHANGED、TRIMMED) に分類
4. 各変更の**リスクスコア**を計算
5. KPI バー、タイムライン、テーブルをレンダリング

差分はブラウザー内で完全に実行されます — アップロード不要、サーバー不要。

### KPI バー

分析後、一列のメトリクスカードが表示されます：

| カード | 表示内容 |
|--------|---------|
| **NEW** | NEW に存在するが OLD に対応クリップがないクリップ |
| **EXTENDED** | OLD と NEW の間で時間が増加したクリップ |
| **CHANGED** | 同じクリップ名だが素材またはテイクが異なる |
| **TRIMMED** | 時間が短縮したクリップ |
| **HIGH RISK** | 即座の対応が必要なイベント (§5 参照) |
| **+DUR** | 追加されたスクリーンタイムの合計 (NEW + EXTENDED フレーム) |
| **−DUR** | 削除されたスクリーンタイムの合計 (TRIMMED フレーム) |
| **% Changed** | 変更されたカットの割合 |

## 4. 差分タイプの理解

エンジンは各 NEW クリップを**同じクリップ名とリール**の OLD クリップと比較します。マッチが見つかった場合、小さな許容範囲内 (時間 ±2 フレーム、source-in ±4 フレーム) で時間とソースイン点を比較して差分タイプを決定します。

### NEW
```
OLD: [なし]
NEW: [████████ CLIP_A ████████]
```
クリップが NEW に存在するが、OLD のどこにも**同じ識別のクリップがない**。すべての NEW イベントは自動的に**高リスク**です。

### EXTENDED
```
OLD: [████████ CLIP_B ████████]         (200 フレーム)
NEW: [█████████████ CLIP_B █████████]   (260 フレーム + 60 フレーム追加)
```
同じクリップだが、NEW バージョンが**長い**。VFX では通常、VFX 作業ウィンドウの拡張が必要です。

### TRIMMED
```
OLD: [█████████████ CLIP_C █████████]   (180 フレーム)
NEW: [████ CLIP_C ████]                  (80 フレーム — 100 フレーム削除)
```
同じクリップだが、NEW バージョンが**短い**。VFX では、作業が予算より遅く始まるか早く終わる可能性があります。

### CHANGED
```
OLD: [████ CLIP_D (srcIn=00:42:15:00) ████]
NEW: [████ CLIP_D (srcIn=01:12:30:08) ████]   同名、完全に異なるソース
```
同じクリップ名だが、ソースタイムコード (srcIn) が許容範囲を超えて異なります。これは、別のテイク、リタイムまたは再グレードされたバージョン、同名の置換クリップを示します。

### UNCHANGED
```
OLD: [████ CLIP_E ████]  (srcIn=00:10:00:00, dur=120fr)
NEW: [████ CLIP_E ████]  (srcIn=00:10:00:00, dur=120fr) — 同一
```
両バージョンで許容範囲内でクリップが同一。デフォルトでは、UNCHANGED イベントはテーブルから**非表示**です。

## 5. リスクスコアリング

すべての差分イベントは、ダウンストリームの作業への影響に基づいてリスクレベルが付与されます。

### リスクレベル

| レベル | 色 | ルール |
|--------|-----|--------|
| **高** | 🔴 赤 | NEW イベント**または** 240 フレーム超 (~10 秒 @24fps) のイベント |
| **中** | 🟡 アンバー | イベント時間 48〜240 フレーム (~2〜10 秒) |
| **低** | 🟢 緑 | イベント時間 48 フレーム未満 (~2 秒) |

### マッチスコア（信頼度 %）

EXTENDED、CHANGED、TRIMMED イベントに対して、エンジンは 0〜100% の**マッチ信頼度**も報告します：

- **100%**：完全一致
- **75〜99%**：小さなトリムまたは小さなソース調整 — 高信頼度
- **50〜74%**：中程度の差異 — 要確認
- **< 50%**：大きな乖離 — 誤マッチの可能性

スコアの計算式：
`(時間類似度 × 60%) + (source-in 類似度 × 40%)`

## 6. タイムラインの読み方

タイムラインは Cut Diff 2.0 の最も強力な部分です。OLD と NEW の両方のカットを水平トラックとして並べて表示します。

### タイムラインレイアウト（上から下）

```
┌─────────────────────────────────────────────────────────────┐
│ RULER  │ 00:00   00:30   01:00   01:30   02:00              │ ← タイムコードルーラー
├────────────────────────────────────────────────────────────┤
│  OLD ░░░░▓▓▓▓▓░░▓▓▓▓░░░░░░▓▓░░░░░░▓▓▓░░░░░░░░░░░░░░░░░░░  │ ← OLD トラック
│ ─────────────────── DIFF ──────────────────────────────────── │ ← 差分セパレーター
│  NEW ░░░▓▓▓▓░░░░░░░▓▓▓▓▓▓░░░▓░░░░░░░▓▓▓░░░░░░░░░░░░░░░░░░  │ ← NEW トラック
│ ▓▓▓░░░░▓▓▓░▓░▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │ ← サマリーストリップ
├────────────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────────┘
```

### NEW トラックと差分カラーバー

NEW トラックは各クリップを差分ステータスを示す**カラーバー**付きで表示します：

| 色 | 差分タイプ | 意味 |
|----|-----------|------|
| 🔵 明るいシアン | NEW | 以前未使用 — OLD に存在しない |
| 🟢 緑 | EXTENDED | このクリップは OLD より長くなった |
| 🟡 アンバー | CHANGED | 同名、異なるソース/テイク |
| 🟣 紫 | TRIMMED | このクリップは OLD より短くなった |
| ⬛ 非常に暗い | UNCHANGED | OLD と同一 |

クリップ上部の **2px 赤ストライプ**は高リスクを意味します。

### コンテンツ差分グラフ

サマリーストリップ下のバーグラフは OLD と NEW 間の**ピクセルレベルのフレーム類似度**を表示します。

| 色 | 意味 |
|----|------|
| 🟢 緑バー | フレームがほぼ同一に見える |
| 🟡 アンバーバー | 中程度の視覚的差異 |
| 🔴 赤バー | フレームが視覚的に大きく異なる |

## 7. ショットカットとその見つけ方

### タイムラインでショットカットを見る方法

**方法 1：NEW トラックのクリップの開始/終了点を確認**

隣接するクリップのカラー差分バーが異なるタイプの場合、重要な編集点の変更があります。

**方法 2：変更されたセクションにズームイン**

タイムライン上で**スクロールホイールでズーム**します。ズームインすると、ルーラーの目盛りが細かくなり、個々のショットが見えてきます。

**方法 3：サマリーストリップのクラスターに注目**

サマリーストリップはカット全体を 1 本のバーに圧縮して表示します。色のクラスター（シアン/アンバー/緑）は密な修正ゾーンを示します。

**方法 4：OLD と NEW のクリップエッジを直接比較**

テーブルで TRIMMED イベントを選択します。インスペクターに OLD と NEW の `RecIn`/`RecOut` 値が表示されます。差分がカット点の移動量です。

### 既存ショット間に挿入された NEW クリップ

既知のクリップ間に NEW クリップが挿入されると、その後のクリップのレコードイン タイムコードがシフトします：

```
OLD:  [──A──|──B──|──C──]      B は 01:00:00:00 から始まる
NEW:  [──A──|NEW X|──B──|──C──]  B は今 01:00:12:00 から始まる
```

NEW カットの B は UNCHANGED（同じコンテンツ）ですが、プログラム内で**後ろ**に現れます。これは次の部門に影響します：
- **音楽エディター**：B のアクションビートに合わせた楽曲は 12 秒遅れる
- **サウンドエディター**：B に同期したフォーリーとエフェクトはリタイムが必要
- **VFX**：B 上の VFX ショットは異なるプログラム位置で再生される

## 8. 差分テーブル

テーブルはすべての変更イベントを行として一覧表示します。

### 列ガイド

| 列 | 説明 |
|----|------|
| **●** | リスクピップ — 赤（高）、アンバー（中）、緑（低） |
| **Type** | NEW / EXT / CHG / TRM / UNC バッジ |
| **Reel** | EDL/XML のリールまたはビン名 |
| **Clip** | クリップ名 |
| **SrcIn** | ソースタイムコードイン |
| **Dur** | フレーム単位の時間 |
| **Match%** | 信頼度スコア（バー + %）— NEW イベントは空白 |
| **Status** | レビューステータス：— / ✓ / ⊘ / ?（クリックで切り替え） |
| **Note** | 自由テキストメモフィールド（インスペクターで表示） |

### 行の選択

任意の行をクリックすると：
1. **インスペクター**（右パネル）が開き、完全なイベント詳細が表示される
2. **タイムラインがズーム**してそのイベントが中央に来る
3. **ビデオが** イベントの `RecIn` タイムコードに**シーク**する（ビデオが読み込まれている場合）

## 9. インスペクターパネル

任意の行をクリックして右側のインスペクターを開きます。選択した変更の完全な内訳が表示されます。

### フィールド

```
イベント 3 / 47              ← 全体のイベント番号
Type:    EXTENDED             ← 差分分類
Reel:    A001                 ← リール名
Clip:    105_08_06/01_AB      ← クリップ名
SrcIn:   10:42:15:00          ← NEW のソース開始
SrcOut:  10:42:28:10          ← NEW のソース終了
RecIn:   01:02:45:00          ← レコード（プログラム）開始
RecOut:  01:02:58:10          ← レコード（プログラム）終了
Duration: 318 フレーム
FPS:      24
```

### マッチ情報（EXTENDED / TRIMMED / CHANGED 用）

```
Match Score:  ████████░░  78%  ← 信頼度バー
Reason:       Duration +48fr (+2.0s extended)
Old Clip:     105_08_06/01_AB  ← OLD の同一クリップ
Old SrcIn:    10:42:15:00      ← OLD のソース開始
Old RecIn:    01:02:45:00      ← OLD のレコード開始
```

### ステータスとメモ

**ステータス**（クリックまたは Enter で切り替え）：
- **—**（なし）：未レビュー
- **✓**（OK）：確認済み、対応不要
- **⊘**（スキップ）：既知の問題、このパスではスキップ
- **?**（要確認）：フォローアップまたは議論が必要

メモは PDF と XLSX エクスポートの両方に表示されます。

## 10. ビデオ比較

OLD と NEW のビデオファイルを読み込んで、完全な比較パネルを解放します。

### 比較モード

#### Wipe（ワイプ）
縦のスライダーで画面を分割します。スライダーを左右にドラッグして OLD（左）または NEW（右）を表示します。

#### Side by Side（サイドバイサイド、SBS）
OLD が左半分、NEW が右半分で同時に再生されます。両方が同期して再生されます。

#### Split（スプリット）
SBS と同様ですが、各ビデオがそれぞれの半分を完全に埋めます（クロップ）。

#### AB
一度に 1 つのビデオをフルスクリーンで表示します。キャンバスをクリックして A（OLD）と B（NEW）を切り替えます。

#### Diff（差分）
**ピクセル単位の差異画像**を表示：同一のピクセルは黒く、異なるピクセルは明るく表示されます。

#### Heat（ヒートマップ）
Diff と同様ですが、大きさに応じた色コード：
- 🟢 緑：小さな変化
- 🟡 アンバー：中程度の変化
- 🔴 赤：大きな変化

### Chain モード

Chain が有効な場合、イベントを選択すると OLD ビデオが自動的に **OLD クリップのソースイン**にシークし、NEW も NEW クリップのソースインにシークします。CHANGED イベントをレビューする際に Chain を使用します。

## 11. フィルター

### タイプフィルター

ピルボタンをクリックして特定の差分タイプのみを表示：

`ALL` `NEW` `EXTENDED` `CHANGED` `TRIMMED`

### リスクフィルター

`all` `high` `med` `low`

**high** をクリックして高リスクイベントのみを表示します。ターンオーバーレビューの推奨スタートポイントです。

### フィルターの組み合わせ

フィルターは組み合わせ可能です：タイプフィルターとリスクフィルターの両方が適用されます。NEW ショット以外の高リスク変更を見るには、type=EXTENDED と risk=high を設定します。

## 12. ステータスとメモのワークフロー

### 推奨レビューパス

1. **HIGH RISK にフィルター** → すべての HIGH アイテムをレビュー → ✓（OK）または ?（要確認）としてマーク
2. **CHANGED にフィルター** → 各テイク置き換えを確認 → VFX の再作業が必要な場合はメモ
3. **NEW にフィルター** → コーディネーターと新ショットを確認 → プル/納品日をメモ
4. **EXTENDED にフィルター** → VFX ショットが予算を超えて延長されていないか確認
5. **TRIMMED にフィルター** → 短縮されたウィンドウ内にデリバラブルが収まることを確認

### 実際のステータスの意味

| ステータス | 使用タイミング |
|-----------|-------------|
| **—** | 未レビュー |
| **✓ OK** | レビュー済み、対応不要、安全に進行可能 |
| **⊘ スキップ** | 既知/意図的、このセッションではスキップ |
| **? 要確認** | 対応前にエディター/コーディネーターへの確認が必要 |

## 13. エクスポート

アンバーの **Export ▾** ボタンをクリックしてエクスポートメニューを開きます。

### Pull EDL

**NEW、CHANGED、EXTENDED** イベントのみを含む CMX 3600 EDL を生成します。ステータスが **⊘ スキップ**のイベントは除外されます。

### PDF レポート

新しいブラウザータブに印刷準備済みの PDF を開きます：
- **サマリーヘッダー**：プロジェクト名、OLD/NEW ファイル名、日付、統計チップ
- **変更カード**：変更されたイベントごとに 1 枚のカード、タイプ別にグループ化
- **音声変更リスト**：音声トラッククリップの別テーブル

### XLSX 変更リスト

**サムネイル画像が埋め込まれた** `.xlsx` ワークブック（4 シート）をエクスポート：

| シート | 内容 |
|--------|------|
| **Change List** | 120×68 サムネイル付きすべての変更イベント |
| **Audio Ref** | RecIn でソートされたすべてのイベント、音声用フラグ付き |
| **Removed** | OLD に存在するが NEW に存在しないクリップ |
| **Summary** | 統計概要：件数、時間 |

## 14. キーボードショートカット

| キー | アクション |
|------|-----------|
| `↓` または `J` | テーブルの次のイベント |
| `↑` または `K` | テーブルの前のイベント |
| `Enter` | 選択イベントのステータスを切り替え |
| `Escape` | インスペクターパネルを閉じる |
| `Space` | 再生 / 一時停止 |
| `←` | 1 フレーム戻る |
| `→` | 1 フレーム進む |

## 15. ヒントとワークフロー例

### ヒント 1：タイムラインから外側へ作業する

テーブルから始めないでください — タイムラインから始めます。サマリーストリップは変更が集中している場所を示します。密集したクラスターにズームイン、ショット境界を見つけ、個々のイベントをクリックしてインスペクターに深く入ります。

### ヒント 2：Wipe モードでフレーミング変更を確認

マッチスコアが高い (>75%) CHANGED イベントは、エディターがわずかに異なる開始フレームを使用したことを意味することが多いです。Wipe モードに切り替えて、ショットの最初のフレームにスクラブします。

### ヒント 3：サイレントリプレイスにコンテンツ差分グラフを活用

コンテンツ差分グラフは EDL が捕捉できない変更を捕らえます。NEW トラックのカラーバーがない領域のグラフにスパイクが見られる場合、クリップ名/タイムコードは同一ですが、コンテンツが視覚的に異なります。

### ヒント 4：最も複雑な問題には HIGH + CHANGED をフィルター

高リスク + CHANGED タイプの組み合わせは最も要求の高いシナリオです：既存の長いショットが別のテイクに置き換えられています。type=CHANGED と risk=high を設定してこれを分離します。

### ヒント 5：メモを納品メモとして使用

レビュー中に Note フィールドに直接アクションアイテムを入力します。XLSX をエクスポートすると、すべてのメモがスプレッドシートに入り、VFX コーディネーターや音楽エディターと共有する準備が整います。

### ヒント 6：テイク比較に AB モードを使用

CHANGED イベントをレビューする際、AB モードに入り、イベントを選択し、キャンバスをすばやくクリックして A/B を切り替えます。Chain モードが両方のビデオをショット開始に合わせているため、まったく同じシーンの OLD テイクと NEW テイクを切り替えています。

### ヒント 7：大規模コンフォームにはマルチパート EDL を活用

シーケンスの変更イベントが 1,500 件を超える場合、Pull EDL エクスポートは自動的に複数のファイルに分割されます（パート1、パート2、…）。
